## 0. 전환 배경 및 동기

### 현재 문제 인식

| 문제 | 상세 |
|------|------|
| **스탯 페이지 사용성 부족** | 31명 전체 테이블 나열 → 클릭 → 프로필 → 스탯 전환의 복잡한 과정. 자동화 후 운영자 본인도 안 보게 됨 |
| **뉴스와 스탯 분리** | 따로 페이지가 나뉘어져 연계되지 않는 느낌. 데이터와 콘텐츠가 상호 맥락을 제공하지 못함 |
| **차별점 불명확** | FotMob(스탯), Reddit(해외 반응)이 각각 존재. "왜 KFN에서 봐야 하는가?"에 대한 답이 약함 |
| **타겟 재정의 필요** | 기존 타겟(크리에이터 B2B + 헤비팬 B2C) 외에 "대충 요즘 잘하는지만 알고 싶은 캐주얼 팬"이 더 큰 시장 |
| **BM 한계** | 축구팬은 돈을 잘 안 쓰는 경향. 현재 타겟으로는 수익화가 어려움 |

### 벤치마킹: 환산주스탯 (maplescouter.com)

메이플스토리 데이터 사이트. 핵심 성공 요인:

| 요인 | 환산주스탯 | KFN 적용 |
|------|-----------|----------|
| **게임 내 없는 데이터 제공** | 환산 스탯, 보스컷 효율 등 게임에서 안 보여주는 데이터 | 해외 현지 여론 + 국내 여론 비교 (기존 서비스에 없는 것) |
| **검색 → 즉시 데이터** | 캐릭터명 검색 → 한 페이지에 핵심 정보 | 선수 클릭 → 스탯 + 여론 통합 페이지 |
| **점진적 깊이** | 기본 정보(`/info`) → 심화 분석(`/result`) | 폼 요약 → 여론 온도 → 타임라인 → 상세 스탯 |
| **메인 랭킹으로 흥미 유발** | Top10 랭킹 + 인기 캐릭터 | 이번 라운드 핫 선수 + 뉴스 헤드라인 |

### 전환 방향 한 줄 요약

> **News/Stats 분리 구조 → "선수 중심 통합 포맷"으로 전환.**
> FotMob = 숫자, Reddit = 의견, **KFN = 숫자 x 의견 = 맥락.**

### 동료(시현) 피드백 요약

- "오 좋아졌다", "벤치마킹에서 시작하는거 아주 좋지", "포인트가 확실히 맞다"
- **주의사항**: "경계하는게 오버엔지니어링. 가볍게 출발하자"
- 시각 자료는 무료 데이터/스크린캡쳐로 시작, 저작권 문제없는 것부터

## 1. 타겟 유저 재정의

### Primary: 캐주얼 해외축구 팬 (신규)

> "한국 축구 관심은 있는데 경기 평가를 할 정도가 아니고, **선수들이 대충 요즘 잘하는지만 알고 싶은 사람들**"

- 경기를 직접 안 보지만 결과/반응은 궁금한 층
- "해외 반응 번역" 유튜브 조회수 수십만이 이 수요를 증명
- **이 유저가 가장 많고, KFN이 가장 잘 서빙할 수 있는 유저**

### Secondary: 헤비 축구팬 (기존 유지)

- 경기 직후 해외 반응 검색, 데이터 깊이 탐색
- 상세 스탯 + 여론 아카이빙까지 소비

### Tertiary: 축구 크리에이터 (기존 B2B, 후순위로 조정)

- 영상/글 소스로 활용
- v2에서는 우선순위 낮춤 (캐주얼 팬 만족이 먼저)

## 2. 핵심 차별점: 데이터 x 여론 = 맥락

### KFN만의 고유 가치

| 기존 서비스 | 제공하는 것 | 제공하지 못하는 것 |
|------------|-----------|-------------------|
| **FotMob/SofaScore** | 선수 스탯 숫자 | 그 숫자의 의미, 현지 평가 |
| **Reddit/커뮤니티** | 해외 팬 의견 | 그 의견의 데이터 근거 |
| **해외 반응 유튜브** | 번역된 해외 반응 | 국내 반응과의 비교, 체계적 아카이빙 |

**KFN = 숫자에 맥락을 입히고, 여론에 근거를 더하는 서비스**

### 킬러 피처: Pattern B — 데이터-여론 갭 분석 + 국내 vs 해외 비교

2가지 비교 축:

| 축 | 내용 | 예시 |
|----|------|------|
| **데이터 vs 여론** | 스탯 수치와 팬 평가의 갭 | 평점 6.8인데 현지 긍정 72% → "스탯에 안 잡히는 기여" |
| **국내 vs 해외** | 한국 팬과 현지 팬의 시각차 | 국내 긍정 78% vs 해외 긍정 91% → "MLS 수준 논란" |

데이터-여론 갭 4가지 경우:

| 데이터 | 여론 | 해석 |
|--------|------|------|
| 좋음 | 좋음 | "수치대로 활약, 현지도 인정" |
| 좋음 | 나쁨 | "스탯은 좋지만 기대치가 높은 선수" |
| 나쁨 | 좋음 | "수치 밖 기여를 현지가 알아봄" — **가장 흥미로운 케이스** |
| 나쁨 | 나쁨 | "부진, 현지도 우려" |

국내 vs 해외 비교가 킬러인 이유:
- "한국에서는 이렇게 보는데 현지에서는 저렇게 본다" → **갭 자체가 콘텐츠**
- 팬들이 SNS에 공유하고 싶어하는 요소 (바이럴)
- 기존 어떤 서비스도 이 비교를 체계적으로 하지 않음

## 3. 메인 페이지 — 큐레이션 설계

### 설계 원칙

- **모든 31명 선수가 어딘가에는 등장해야 함**
- 테이블 나열이 아닌 **이미 큐레이션된 형태**로 보여줌
- 유저가 선택하기 전에 이미 흥미로운 정보가 보임
- 리그별 그룹핑이 **안전망** 역할 (어떤 선수도 빠지지 않음)

### 큐레이션 카테고리

#### 경기 결과 기반 (매 라운드 자동 갱신)

| 카테고리 | 대상 | 커버 범위 | 갱신 주기 |
|---------|------|----------|----------|
| **이번 라운드 활약 선수** | 평점 상위 or 공격포인트 기록 | 활약한 3~5명 | 매 라운드 |
| **이번 라운드 출전 선수** | 해당 라운드 경기 뛴 모든 선수 | 출전한 15~20명 | 매 라운드 |
| **다음 라운드 경기 예정** | 이번 주 경기가 있는 선수 | 예정된 10~15명 | 주 1회 |

#### 시즌 누적 기반 (주 1회 갱신)

| 카테고리 | 대상 | 커버 범위 |
|---------|------|----------|
| **시즌 공격포인트 랭킹** | 골+어시 누적 상위 | 공격수/미드 중심 |
| **출전 시간 랭킹** | 시즌 누적 출전 시간 순 | 주전 경쟁 선수 |
| **시즌 평점 추이 상승/하락** | 최근 5경기 vs 시즌 평균 비교 | 변화가 있는 선수 |

#### 리그별 그룹핑 (항상 고정)

| 카테고리 | 대상 | 커버 범위 |
|---------|------|----------|
| **리그별 선수 그룹** | EPL / 분데스 / 라리가 / 스코티시 / MLS 등 | **31명 전원 커버** |

#### 여론 기반 (KFN 고유)

| 카테고리 | 대상 | 커버 범위 |
|---------|------|----------|
| **현지 반응이 뜨거운 선수** | 여론 볼륨이 높은 선수 | 화제성 있는 선수 |
| **국내 vs 해외 온도차가 큰 선수** | 평가 갭이 큰 선수 | Pattern B 연계 |

- 소스 출처를 항상 명시 → **유저가 직접 판단 가능**
- 전문 매체 의견과 커뮤니티 의견을 구분 표시
- 국내/해외 각각 복수 소스 확보

### 영상-선수 매칭 로직

영상 자체가 선수 전용일 필요 없음. **경기 하이라이트 영상 → 댓글에서 선수 언급 검색** 방식.

```
[Step 1] 경기 영상 찾기
  KFN 경기 데이터: 손흥민이 3/22 오스틴전 출전
  → YouTube Data API v3: search.list
  → 검색 쿼리: "{팀명} vs {상대팀}"
  → 채널 필터: Tier 1~2 채널 ID 리스트
  → 업로드일 필터: 경기일 ±48시간
  → 결과: 하이라이트 영상 3~5개

[Step 2] 댓글 수집
  → YouTube Data API v3: commentThreads.list
  → 상위 200~500개 댓글 수집 (페이지네이션)

[Step 3] 선수 언급 필터링
  → 선수명 사전으로 댓글 텍스트 필터링
  → 매칭된 댓글만 추출하여 여론 데이터로 저장
  → 소스 메타데이터: 채널명, 영상 ID, 댓글 작성자, 원문
```

### 선수명 매칭 사전 (예시)

| 선수 | 매칭 키워드 (해외 채널용) | 매칭 키워드 (국내 채널용) |
|------|------------------------|------------------------|
| 손흥민 | "Son Heung-min", "Son", "Sonny", "Heung-min" | "손흥민", "흥민", "쏘니" |
| 김민재 | "Kim Min-jae", "Minjae", "Kim" + 팀명 필수 | "김민재", "민재" |
| 이강인 | "Lee Kang-in", "Kang-in", "Kangin" | "이강인", "강인" |
| 황희찬 | "Hwang Hee-chan", "Hee-chan", "Hwang" | "황희찬", "희찬" |
| 정우영 | "Jeong Woo-yeong", "Wooyeong", "Jeong" | "정우영", "우영" |

> 전체 31명 선수 매칭 사전은 `docs/player-search-registry.md` 확장하여 관리.
> "Son", "Kim" 등 일반적인 단어는 팀명 동시 포함 조건 필수 (오탐 방지).

### YouTube API 비용 추정

```
YouTube Data API v3 (무료 일일 쿼터: 10,000 유닛)

search.list: 100 유닛/요청
commentThreads.list: 1 유닛/요청

선수 1명당:
  검색 1회 (100) + 댓글 수집 ~5회 (5) = 약 105 유닛

31명 전원 (1 라운드):
  31 × 105 = 약 3,255 유닛

→ 일일 쿼터 10,000 내에서 충분히 처리 가능
→ 주당 2~3 라운드 수집해도 여유
```

## 7. 여론 파이프라인 아키텍처 — Skill 기반 병렬 수집

### 기존 구조 (v1)

n8n 단일 워크플로우에서 모든 소스 순차 수집

### 신규 구조 (v2)

각 소스를 독립된 Claude Skill로 구현, 오케스트레이터가 병렬 실행

```
              ┌──────────────────────────┐
              │   opinion-pipeline       │
              │   (오케스트레이터 Skill)   │
              │                          │
              │  입력: 선수ID + 경기정보   │
              └───────────┬──────────────┘
                          │
          ┌───────────────┼───────────────┐
          │               │               │
     ┌────▼────┐   ┌─────▼─────┐  ┌─────▼──────┐
     │ 해외    │   │ 국내      │  │ YouTube   │
     │ 소스    │   │ 소스      │  │ 소스      │
     └────┬────┘   └─────┬─────┘  └─────┬──────┘
          │               │              │
     병렬 실행        병렬 실행       병렬 실행
          │               │              │
   ┌──────┴───┐   ┌──────┴────┐  ┌──────┴───────┐
   │ reddit   │   │ fmkorea   │  │ youtube      │
   │ -opinion │   │ -opinion  │  │ -opinion     │
   │ Skill    │   │ Skill     │  │ Skill        │
   │ (기존)   │   │ (신규)    │  │ (신규)       │
   ├──────────┤   ├───────────┤  │ 해외+국내 통합│
   │ media    │   │ dcgall    │  └──────────────┘
   │ -opinion │   │ -opinion  │
   │ Skill    │   │ Skill     │
   │ (신규)   │   │ (신규)    │
   └──────┬───┘   └──────┬────┘
          │               │
          └───────┬───────┘
                  │
         ┌────────▼──────────────────┐
         │   결과 통합 + AI 분석      │
         │                           │
         │  • 소스별 긍정/부정 비율    │
         │  • 국내 vs 해외 비교       │
         │  • 온도차 분석 텍스트 생성  │
         │  • JSON 저장               │
         └───────────────────────────┘
```

### 각 Skill 정의

| Skill | 입력 | 출력 | 상태 | 구현 난이도 |
|-------|------|------|------|-----------|
| **reddit-opinion** | 선수명 + 팀 서브레딧 | 매치스레드 댓글 + 감성분석 | 기존 완료 | - |
| **youtube-opinion** | 선수명 + 경기정보 + 채널 리스트 | 댓글 필터링 결과 (해외+국내) | 신규 | 하 (API 제공) |
| **fmkorea-opinion** | 선수명 + 경기 키워드 | 관련 게시글/댓글 | 신규 | 중 (스크래핑) |
| **dcgall-opinion** | 선수명 + 경기 키워드 | 관련 게시글/댓글 | 신규 | 중 (스크래핑) |
| **media-opinion** | 선수명 + 리그 매체 목록 | 기사 본문 + 평가 | 신규 | 중-상 (매체별 파싱) |
| **opinion-pipeline** | 선수ID + 경기정보 | 통합 여론 JSON | 오케스트레이터 | 중 |

### 구현 우선순위

| 순서 | Skill | 이유 |
|------|-------|------|
| 1 | **reddit-opinion** | 이미 완료 |
| 2 | **youtube-opinion** | API 제공, 구현 가장 쉬움. 하나의 Skill로 해외+국내 채널 동시 커버 |
| 3 | **fmkorea-opinion** | 국내 여론 핵심 소스 |
| 4 | **dcgall-opinion** | 에펨과 유사 구조, 3번과 병행 구현 가능 |
| 5 | **media-opinion** | 매체별 파싱이 가장 복잡, 후순위 |
| 6 | **opinion-pipeline** | 위 Skill들이 2개 이상 완료된 후 오케스트레이터 구현 |
